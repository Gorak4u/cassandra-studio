# Cassandra Studio 1.0.0

The first release of Cassandra Studio: one desktop app to connect to, query, browse, monitor and
operate Apache Cassandra clusters. Requirement IDs refer to `requirement.txt`.

Guides: [user guide](../guide/user-guide.md), [install and admin guide](../guide/install.md),
[runbooks](../guide/runbooks/README.md). The guides are also built into the app (the **?** button on
every panel) and work offline.

## Supported versions and platforms

| | Supported |
|---|---|
| Cassandra | 3.11, 4.0, 4.1, 5.0, on Java 8, 11 or 17, in the same session (NFR-COMPAT). Verified live on 3.11.19 (Java 8), 4.1.12 (Java 11) and 5.0.9 (Java 17). Newer versions degrade gracefully: unknown metrics are hidden, unavailable operations say so. |
| Windows | 10 and 11, x64 (`.exe` installer, per-user) |
| macOS | 12 or later, Apple Silicon and Intel (`.dmg`) |
| Linux | Ubuntu 20.04+ / Debian (`.deb`), RHEL / Rocky 8+ (`.rpm`), any x64 distribution (`.AppImage`) |
| Runtime | Java 21 bundled; nothing else to install (NFR-PLAT) |

## Features by area

### Connections (CON)

- Create, edit, clone, delete and test connections (CON-1); folder tree with search and
  drag-and-drop (CON-2); DEV / TEST / STAGING / PROD environments (CON-3).
- CQL settings: contact points, local DC, protocol version, consistency, timeout, page size,
  PasswordAuthenticator, TLS with JKS, PKCS12 or PEM and mutual TLS (CON-4).
- All nodes in all DCs discovered from the contact points (CON-5).
- JMX access per connection: SSH tunnel to localhost JMX (also through a bastion), direct JMX with
  optional SSL and authentication, jmx_exporter, with automatic jmx_exporter fallback when JMX fails
  (CON-6, CON-7).
- Secrets in the OS keychain, encrypted file fallback (CON-8). Import and export without secrets
  (CON-9). Several clusters open at once (CON-11). Read-only connections (CON-12).

### CQL editor (CQL)

- Multi-tab editor with highlighting and schema-aware completion (CQL-1); run statement, selection
  or script (CQL-2); run on a chosen coordinator node in any DC (CQL-3); consistency, page size and
  tracing (CQL-4).
- Result grid with sort, filter, next page and fetch all, CSV and JSON export (CQL-5); trace view
  (CQL-6); messages with server warnings (CQL-7, ALR-2); searchable history and a saved script
  library (CQL-8); editing rows in the grid with generated CQL (CQL-9); `USE`, `CONSISTENCY`,
  `TRACING`, `DESCRIBE` on every version (CQL-10).

### Schema and security (SCH, SEC)

- Schema tree, keyspace and table details, DDL (SCH-1, SCH-2, SCH-3, SCH-5); create and drop
  forms that show the CQL first (SCH-4).
- Roles with login, superuser and memberships (SEC-1); create, alter, drop, grant and revoke
  (SEC-2); `system_auth` replication warning (SEC-3); effective permissions including inherited
  ones (SEC-4).

### Monitoring and health (MON, ALR)

- Live JMX metrics per node with version- and GC-aware metric catalogues for 3.11, 4.0, 4.1 and
  5.0 (MON-1, MON-2); 24 h in-memory history (MON-3); PNG and CSV export of every chart (MON-4).
- Health, cluster, node, token, ring, load and disk, GC, reads and writes, and table views
  (MON-10 … MON-18).
- 12 health rules with per-cluster thresholds (ALR-1).

### Operations (OPS)

- 12 nodetool views over JMX: status, info, ring, describecluster, tpstats, tablestats,
  tablehistograms, proxyhistograms, gossipinfo, compactionstats, netstats, getendpoints (OPS-1).
- Flush, major and user-defined compaction, cleanup, scrub, upgradesstables, garbagecollect on a
  set of nodes with progress and cancel (OPS-2).
- Repair: full, incremental, sub-range, -pr, by DC, with live progress and cancel (OPS-3).
- Snapshots: take, list, clear (OPS-4).

### Diagnostics (JVM, PRF)

- Thread dumps and series with grouping by state and stack, deadlock detection and comparison
  (JVM-1); live top threads by CPU (JVM-2).
- Hot partitions (toppartitions on all nodes at once) (PRF-1); table histograms with large
  partition and tombstone flags, `system.log` warnings, and the estate's tombstone scan (PRF-2).

### GC logs (GCL)

- Load GC logs from a node over SSH (found from the JVM arguments) or upload a file (GCL-1);
  charts (GCL-2); summary statistics (GCL-3); 19 finding rules with tuning hints (GCL-4). Java 8
  and unified logging; CMS, ParNew, G1, Parallel, Serial, ZGC (also generational) and Shenandoah.

### Config (CFG)

- Effective configuration per node: `cassandra.yaml` (virtual table or file), JVM flags, OS limits
  (CFG-1).
- Drift report per cluster or per DC, and comparison with Puppet Hiera from a control repo checkout
  (CFG-2).

### Backups (BAK)

- Providers per cluster with auto-detection: the estate's backup scripts, Cassandra Medusa, or
  snapshots over JMX (BAK-1); catalogue with type, time, size, status, retention and object lock
  (BAK-2); run a backup now for a cluster, DC or node with per-node progress and cancel (BAK-3).

### Bulk (BLK)

- Unload a table (token-range parallel) or a query to CSV or JSON lines, optionally gzip (BLK-1).
- Load CSV or JSON lines with column mapping, TTL and write timestamp, rate limit, dry run and
  reject files (BLK-2).

### Safety, audit and platform (NFR)

- Every write, DDL statement and operation shows the exact CQL or nodetool equivalent and needs
  confirmation; PROD needs the connection name typed; read-only connections refuse changes
  (NFR-SAFE).
- Local audit log of every change and every blocked attempt, exportable (NFR-AUD).
- Secrets in the OS keychain, TLS where configured, no telemetry, no connections except to your
  clusters (NFR-SEC).
- Studio's database is versioned and migrated on upgrade; an older Studio refuses a newer database
  instead of damaging it (NFR-DATA).
- Light and dark theme, keyboard shortcuts (NFR-UX); keyboard and screen-reader accessible, axe
  checked (NFR-A11Y).
- A lost node or JMX connection never freezes the UI; the node shows as unreachable and is retried
  with back-off (NFR-RELI).
- User guide, install guide, runbooks, in-app help and these release notes (NFR-DOCS).
- Corporate networks (NFR-NET): HTTP(S) proxy (system or manual, password in the keychain), SSH through
  HTTP CONNECT or SOCKS5 proxies, a global CA bundle and optional OS trust store for CQL TLS, JMX TLS and
  HTTPS; offline mode for air-gapped sites; the build fails on any external URL (NFR-SEC: no telemetry).
- Update check (NFR-UPD): a banner links to a newer GitHub release; never downloads; can be turned off.
- Open-source dependencies under Apache-2.0, MIT, BSD or EPL licences (NFR-LIC).

## Known limits

- **Installers are not code-signed yet** (NFR-SIGN): Windows SmartScreen and macOS Gatekeeper warn;
  see the install guide for the workaround. Signing is switched on in the release workflow as soon as
  the certificates are available.
- Proxies: "System" mode reads environment variables and Java properties only (no OS proxy settings or
  PAC files: choose Manual on Windows and macOS); Basic proxy authentication only. A changed CA bundle
  applies to new connections.
- **No Studio Server** (team mode, shared catalogue, scheduled repair and backups, alert
  notifications, SSO, RBAC): planned for v1.1. No access control between users (decision Q-1).
- Backups: no verification, restore or schedules (BAK-4 … BAK-6); Medusa support has not been
  tested against a live Medusa installation. Custom backup providers (BAK-8) are not available.
- Repair is on demand only; segmented and scheduled repair and Reaper integration (REP) come in v1.1.
- Bulk: local files only (no S3 or GCS), no exact row counts or cluster-to-cluster copy (BLK-3 …
  BLK-6).
- Monitoring history is kept in memory and lost on restart; disk usage needs SSH. No custom
  dashboards or node comparison (MON-5, MON-6); thread pool, compaction and streaming views are
  available as nodetool views in Operations rather than dedicated dashboards.
- The Apache Cassandra Sidecar access method is listed but not implemented.
- Jobs, thread dumps, GC log analyses and collected config are kept in memory only.
- No address mapping for clusters whose nodes advertise addresses your machine cannot reach.
- No log file: the engine logs to standard error (see the install guide).
- Not yet done in this release: CSV import in the editor (CQL-11), schema compare (SCH-6), node log
  viewer (ALR-3), drain/gossip and decommission operations (OPS-5, OPS-6), heap histograms and JFR
  (JVM-3, JVM-4), runtime config changes and upgrade readiness (CFG-3, CFG-4), Hiera connection
  import (CON-10).
- Bulk load throughput on a busy 4-core test host was 4,000–20,000 rows/s (below the 10,000 rows/s
  goal on the 3-node 4.1 cluster under load); unload 29,000–145,000 rows/s.
